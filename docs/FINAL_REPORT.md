# Mini-htop: Real-time System Monitor

## 1. Project overview

Mini-htop is a terminal-based system monitoring tool. It displays CPU, memory,
swap, disk, and process information in real time. Users can search and sort
processes and send `SIGTERM` or `SIGKILL` after confirming the operation.

The project demonstrates how an operating system exposes resource and process
information to user-space programs. Its primary demonstration environment is
Linux or WSL.

## 2. Objectives

- Observe total and per-core CPU usage.
- Observe RAM, swap, and disk usage.
- Inspect and filter running processes.
- Demonstrate process management with POSIX signals.
- Read Linux kernel data from the `/proc` virtual filesystem.
- Provide a responsive real-time terminal interface.

## 3. Architecture

```text
User
  |
  v
Textual UI (ui/app.py)
  |-------------------------------|
  v                               v
SystemMonitor                 ProcessMonitor
  |                               |
  v                               +-- process enumeration
ProcfsReader                      +-- filtering and sorting
  |                               +-- os.kill()
  +-- os.open()
  +-- os.read()
  +-- os.close()
  |
  +-- /proc/stat
  +-- /proc/meminfo
```

The Textual interface schedules a refresh every second. Resource and process
collection runs outside the UI event loop to prevent the screen from freezing.

## 4. POSIX APIs and operating-system interfaces

### `os.open()`

Opens `/proc/stat` or `/proc/meminfo` and returns a file descriptor. The program
opens these files in read-only mode.

### `os.read()`

Reads bytes from the file descriptor in 4096-byte chunks until end-of-file. This
demonstrates descriptor-based input rather than relying only on a high-level file
helper.

### `os.close()`

Closes the descriptor in a `finally` block so the resource is released even if
decoding or parsing fails.

### `os.kill()` and signals

`os.kill(pid, signal.SIGTERM)` asks a process to terminate gracefully.
`os.kill(pid, signal.SIGKILL)` asks the kernel to stop it immediately. The UI
requires confirmation and prevents the monitor from terminating itself.

### Linux `/proc`

`/proc` is a virtual filesystem generated by the Linux kernel. `/proc/stat`
contains CPU time counters, while `/proc/meminfo` contains memory and swap data.

## 5. Resource calculations

CPU usage is calculated from two samples:

```text
CPU % = (total delta - idle delta) / total delta * 100
```

RAM usage is calculated as `MemTotal - MemAvailable`. Swap usage is calculated
as `SwapTotal - SwapFree`. Values reported in KiB are converted to bytes.

## 6. Features

- Total and per-core CPU gauges
- RAM, swap, and disk gauges
- Live process table
- Search by process name or PID
- Sort by CPU, memory, PID, or name
- Pause and manual refresh controls
- Confirmed `SIGTERM` and `SIGKILL` operations
- Linux `/proc` data collection with cross-platform fallback

## 7. Safety and error handling

The program should be run as a normal user. The demonstration must use only test
processes created by the team. Permission errors, missing processes, and transient
process changes are caught and shown in the status bar instead of stopping the UI.

## 8. Testing

Automated tests verify CPU parsing, memory parsing, CPU delta calculations, and
descriptor-based file reading. The final demonstration should also verify that the
status bar reports `source: /proc` on Linux or WSL.

## 9. Limitations and future work

- Process enumeration and disk usage still use `psutil`.
- Direct `/proc` mode is Linux-specific.
- Historical graphs are not stored.
- A future version could read `/proc/[PID]` directly, verify process identity
  before sending a signal, and export usage history.

## 10. Conclusion

Mini-htop demonstrates resource monitoring, the Linux `/proc` interface,
file-descriptor operations, and POSIX process signals in a usable real-time tool.
It connects operating-system concepts with an interactive program that can be
demonstrated safely on Linux or WSL.
